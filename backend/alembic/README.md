# Alembic Migrations

## Generate a migration

```bash
alembic revision --autogenerate -m "phase_0_initial_schema"
```

## Apply migrations

```bash
alembic upgrade head
```

## Roll back one step

```bash
alembic downgrade -1
```

## Notes

- Autogenerate is a starting point, not a final diff. Always review the
  generated script — particularly for enum additions (Alembic does not
  autogenerate enum value additions on Postgres) and JSONB default changes.
- New enums must be explicitly created/dropped in migrations:

  ```python
  listing_status = sa.Enum("draft", "live", name="listing_status")
  listing_status.create(op.get_bind(), checkfirst=True)
  ```

- For Phase 0 the first autogenerated migration should produce the full
  schema defined in [app/models/](../app/models/). Generate, review, commit
  as `alembic/versions/0001_initial_schema.py` (Alembic will assign a random
  ID — rename if you want a sequential prefix).
